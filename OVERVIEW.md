## Purpose

`Source/Public` is the shared dependency root for the entire Populous: The Beginning modernised build. It holds two orthogonal subtrees: `Internal/` carries the first-party **PopTB Platform** abstraction library (headers + implementations), and `External/` carries **third-party vendor libraries** that the game links against. Nothing in this directory is game logic; it is purely infrastructure consumed by modules higher up the tree. The game executable, MapEdit, and all other projects pull their platform headers and third-party includes from here.

## Subdirectories

- [`Internal/`](Internal/OVERVIEW.md) — First-party PopTB Platform abstraction layer: a self-contained Visual Studio project (`PopTB Platform.sln`) containing the `Lb*` / `Pop3*` / `Tb*` headers and their C++ implementations (screen, sprite rendering, input, network, sound, types, math, debug, compression).
- [`External/`](External/OVERVIEW.md) — Third-party vendor libraries bundled with the repo: DirectX 9 SDK (`DX9`), EASTL, SDL 2.0.5, SFML 3.1.0, ffmpeg, Poco 1.6.1, and Snappy.

## Key types and entry points

These are defined in `Internal/PopTB Platform/PopTB Platform/`:

- **`Pop3Types.h`** — Platform-independent type aliases (`DWORD`, `BYTE`, `WORD`, etc.) that shadow Win32 types without including `<Windows.h>`, keeping game headers clean. See [`Pop3Types.md`](Internal/PopTB%20Platform/PopTB%20Platform/include/Pop3Types.md)
- **`Pop3App`** (`Pop3App.h/.cpp`) — Static class owning the application lifecycle: `init()`, window/HWND management, SDL2 vs. Win32 event dispatch. See [`Pop3App.md`](Internal/PopTB%20Platform/PopTB%20Platform/include/Pop3App.md)
- **`Pop3Lib.h`** — Umbrella header that re-exports the full public API surface in one `#include`. See [`Pop3Lib.md`](Internal/PopTB%20Platform/PopTB%20Platform/include/Pop3Lib.md)
- **`LbScreen` / `Pop3Screen`** — Screen-mode and surface lifecycle abstractions (resolution, flip, palette).
- **`LbSprite` / `LbSpriteRender`** — Sprite blitting and font rendering primitives.
- **`Pop3Network` / `Pop3NetworkUDP`** — Network abstraction used by multiplayer (wraps Poco + OS sockets).
- **`Pop3Sound`** — Audio subsystem header (wraps SFML audio or platform equivalent).
- **`Pop3Compress`** — Compression helpers (backed by Snappy in `External/`).

## Internal relationships

Within `Internal/PopTB Platform/`, the headers form a layered dependency: `Pop3Types.h` has no dependencies and is included by nearly everything else; `Pop3Build.h` sets compile-time feature flags (`POP3_BUILD_USE_SDL2`, etc.) that gate SDL2 vs. Win32 code paths throughout the other headers; `Pop3Lib.h` is the single umbrella include that pulls in the full public surface. The `src/` C++ files implement the headers and are compiled as a separate static library project — they do not include each other's internals.

`External/` libraries are independent of each other and of `Internal/`; they are consumed by `Internal/` source files (e.g. Snappy for `Pop3Compress`, SFML for `Pop3Sound`, SDL2 for the SDL2 build path).

## External dependencies

- **`External/DX9`** — DirectX 9 SDK headers and `.lib` files (used by the hardware renderer path in `Internal/`).
- **`External/EASTL`** — EA Standard Template Library, used project-wide as an STL replacement.
- **`External/SDL2-2.0.5`** — SDL2 windowing/input/audio, activated when `POP3_BUILD_USE_SDL2` is set.

- **`External/snappy`** — Fast compression library for `Pop3Compress`.

## Caveats

- The `Pop3Types.h` header deliberately excludes `<Windows.h>` to keep the type surface clean; do not add Win32 includes to it. The `#ifndef` guards are carefully matched to the Windows SDK macros — any type added here must respect those guards.
- `Pop3Build.h` controls feature flags for SDL2 vs. Win32 and debug vs. release builds. Changes there ripple across virtually every file in `Internal/`; review all affected `#if POP3_BUILD_*` branches before modifying.
- The bootstrap input for this directory listed only `Internal/` as a child and zero direct files; the actual tree also contains `External/` (verified by directory inspection). Any scanner re-run should capture both subtrees.
