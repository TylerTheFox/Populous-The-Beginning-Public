## Purpose

This directory is the implementation core of the **PopTB Platform** static library — the cross-platform OS, rendering, input, audio, and networking substrate that the game proper sits on top of. It is pulled in by virtually every other part of the project. Its responsibilities span Win32/SDL2 window management, a two-layer rendering pipeline (software 8bpp framebuffer composed onto a D3D9 hardware surface), 2D sprite drawing, palette management, input dispatch, UDP multiplayer networking, SFML audio, FFmpeg movie playback, and several primitive math/geometry types. It has no dependency on game-simulation or AI code; everything here is plumbing that the game layers consume.

## Internal relationships

The rendering stack flows from bottom to top: `LbSurface`/`LbRenderContexts` manage raw pixel memory → `LbDraw`/`LbSpriteRender` write into it → `LbScreen` manages the back/front surface swap → `Pop3Screen` uploads the finished 8bpp buffer to a D3D9 texture and blits it as a fullscreen quad. `LbDrawBackend` is the seam: it registers all `Lb*` functions into the `Pop3DrawBackend` table so that higher-level code can call through one consistent interface without knowing which implementation is active. `Pop3App` owns the window and pumps messages, forwarding D3D9 device-lost notifications (`WM_D3D9DEVICELOST`) to `Pop3Screen`. `Pop3Debug` is a leaf depended on by nearly everything else.

## Caveats

- **MP determinism — `Pop3App` cursor clipping**: `ClipCursor` in `Pop3App::ProcessWindowsMessages` is a side-effect that touches Win32 state and is non-deterministic across machines; do not call it on the simulation thread.
- **MP determinism — `Pop3Network` file transfer**: the sliding-window retransmit logic uses wall-clock time comparisons; behaviour may diverge under different system clocks.
- **Thread safety — `Pop3Debug`**: uses static buffers and global state; unsafe to call from multiple threads without external locking.
- **Thread safety — `Pop3Input::sortOutSpecialKeys`**: contains `static` locals; unsafe for concurrent call sites.
- **`LbDrawBackend` call order**: `LbDraw_RegisterBackend()` must complete before any call to `LbScreen_Initialise()` or drawing functions; the backend table is uninitialised until then.
- **`Pop3Sound` lazy init**: SFML objects are heap-allocated in constructors to avoid static-initialisation order issues with the CRT; do not change to value-type members without auditing startup order.
- **`TbRect`/`TbPixFmt`/`TbPixelCaps`/`TbRenderArea` stubs**: these files exist solely for backward compatibility; do not add logic to them — put it in the corresponding `Pop3*` file.
